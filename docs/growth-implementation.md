## 页面与职责

| 入口 | 负责什么 |
| --- | --- |
| 规则引擎 → 用户等级 | R1–R3 的使用/商业价值评分、窗口、评估频率、升级门槛、连续降级周期与预览 |
| 规则引擎 → 推广等级 | A1–A3 的注册、首次使用、付费转化、留存、合规与退款门槛，独立评估 |
| 规则引擎 → 权益管理 | 奖励积分有效期、赠送范围/额度、提现开关/限额；定义资产怎么使用 |
| 规则引擎 → 激励规则 | 事件、条件、奖励对象、资产、数量/比例、等级加成、预算、观察期；定义何时获得资产 |
| 激励规则 → 奖励记录 / 任务核验 / 试运行与事件 | 核验业务证据、复核奖励、查看匹配原因和试算结果 |
| 财务 → 提现管理 | 商户能力、提现复核、原单查单、打款尝试、已发生订单退款的渠道核验 |
| 用户管理 → 推广详情 | R/A 结果、定级依据、邀请关系与风险审核；不维护定级规则 |

运营界面复用 FaSearchBar、FaTableHeader、FaTable、Element Plus 抽屉与系统主题。客户端复用设置页、Ant Design 和既有请求/查询缓存层。

规则中心仅保留用户等级、推广等级、权益管理、激励规则四个入口。旧的触达、分类、优先、响应、调研、追踪占位菜单及关联权限已从初始化配置和开发库移除，后续启动不会重新生成。

权益管理不读取一段激励文字执行。两个模块共享结构化资产定义：积分用于消费，可按政策赠送，不能提现；现金可以提现，不能赠送。激励动作引用资产类型，执行后落到账户和流水。

## 初始草案

空库可通过“载入初始规则”建立待配置的初始版本。活动预算默认为 0，赠送/提现默认关闭。上线应先配置并发布权益政策，再发布有预算的激励规则。

R 评分：净实付 30 分（满分基准 3000 元）、有效活跃天数 30 分（30 天）、有效成果 25 分（10 个）、采纳反馈 15 分（5 条）。R1 从 0 分开始；R2 ≥40 分且活跃 ≥5 天、成果 ≥1；R3 ≥70 分且活跃 ≥15 天、成果 ≥3。指标都取配置的统计窗口，不使用客户端自行上传的“分数”。

| 推广等级 | 有效注册 | 首次使用 | 首次付费 | 付费转化率 | 留存率 | 合规率 | 退款率 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| A1 | 5 | 3 | 1 | ≥20% | 不要求 | ≥98% | ≤15% |
| A2 | 20 | 12 | 6 | ≥30% | ≥50% | ≥98% | ≤10% |
| A3 | 60 | 40 | 24 | ≥40% | ≥65% | ≥98% | ≤5% |

同等级条件全部满足才升级；没有达到 A1 为“未定级”。默认窗口 90 天、每月评估、连续两个评估周期不达标才降级。可调整窗口和日/周/月频率。留存只观察已满 30 天的样本及其第 24–30 天活动，默认至少 5 个成熟样本；合规审核覆盖不足 80% 时不把未知当成不合规。证据不足时保留原等级。

| 激励 | 默认奖励 |
| --- | --- |
| 首次有效任务 | 用户与直接邀请人各 2000 积分 |
| 首次购买套餐 | 邀请人按净实付计现金：未定级 3%，A1/A2/A3 为 5%/8%/10% |
| 首次购买流量包 | 邀请人按净实付计现金：未定级 1%，A1/A2/A3 为 2%/3%/5% |
| 有效付费订阅期间每日登录 | 100 积分，每日一次 |
| 采纳反馈 S/A/B/C | 2000/800/400/150 积分；S 级不可配置自动到账 |
| 有效成果 | 1000 积分，默认每日最多 3 次 |
| 共创验收 | 2000 积分，审核后发放 |

普通用户也可以邀请和获得基础现金奖励，不要求先有推广等级。套餐与流量包的首次付费分别判断；续费、重复购买不会反复触发。免费领取不当成付费。

固定奖励支持获奖人的 R 与 A 百分比加成，二者相加后计算并受单次上限约束。实付比例采用获奖人的 A 比例，未定级使用基础比例。所有金额后台按“分”记账，运营表单按“元”输入。

## 邀请与注册

每个产品用户有一个稳定、应用隔离、随机邀请码。官方链接为 `https://www.yxciedu.com/invite/{code}`，二维码与海报使用同一真实链接。

官网 `/invite/:code`、`/register` 使用运营端产品注册服务，不把网站 CMS 账号当产品用户。链接注册和客户端手填邀请码都在注册事务中绑定邀请人。官网允许验证代码或官方链接，错误必须明确显示；清除邀请码才会转为普通注册。

个人资料允许补绑：注册未满 72 小时、从未绑定、没有任何正金额成功支付、没有首个核验通过的任务。绑定一次后不能更换。禁止自身邀请、循环关系、跨应用和停用账号。后补关系不追溯发奖。

客户端“邀请有礼”展示真实统计、邀请记录、奖励明细、活动规则，支持复制代码/链接和下载真实二维码海报。未发布活动时明确显示暂无活动，不显示原型中的虚构人数、Token 额度或到账记录。

## 数据来源与核验

| 数据/事件 | 可信来源 | 客户端或本地服务工作 |
| --- | --- | --- |
| 注册与邀请归属 | 产品认证服务和绑定事务 | 注册提交可选邀请码；个人资料发起补绑 |
| 每日登录 | 服务端认证成功记录 | 正常登录即可，不由页面上报“已奖励” |
| 套餐/流量包首次支付 | 校验签名与金额后的商户支付订单 | 展示订单状态；不得根据前端支付完成回调发奖 |
| 退款 | 渠道签名核验后的退款流水 | 运营提供已经发生的商户退款请求单号，后台查证 |
| 首次任务/有效成果 | 任务核验记录、网关调用证据 | 本地解析/完整审查任务创建和完成时写持久补报队列 |
| 反馈 | 工单首次采纳事务及 S/A/B/C 价值等级 | 原有反馈入口；采纳后等级与状态不允许直接改写 |
| 共创 | 已提交的共创任务及人工验收 | 接入统一任务类型 `cocreate`，由运营核验 |

本地服务只保存应用/用户/网关来源组成的归属键、哈希任务/项目/成果标识与状态。旧的无归属记录不补给新账号。切换账号、重启、网络失败后，只有原账号可以继续补报；重试沿用同一业务标识。单纯 OCR、回放、失败任务不算有效成果。

网关保存本次模型请求与云任务的关联证据。**模型调用成功不等于成果有效**：本地完成声明先进入“任务核验”，人工核验后才触发首次任务/成果；可再经过奖励复核。未实现自动验证本地成果真实性，因此没有把客户端声明直接变成自动到账。

## 执行与账务

- 保存产生新版本；已发布版本保留历史。支持指定生效时间、停止、等级预览与激励试运行。
- 按业务发生时间选规则，并快照当时可用的定级结果、奖励动作、权益有效期及订单关系，避免延迟回调使用后来调高的比例。
- 基础规则按优先级互斥，明确设置的叠加规则另行计算。同一首次任务成果不会同时领取首次任务和成果奖。
- 应用行锁、业务唯一键、账户行锁和账务流水共同处理并发；双向奖励同时预占预算，预算不足不只给其中一方。相同活动编号的版本共享累计预算和次数。
- 默认付费奖励观察 7 天；审核/待到账记录预占预算。停止规则不会取消已经承诺的待到账记录。
- 部分退款按累计退款重算应得奖励，只追加差额冲正；重复查询不重复扣减。现金不足记原获奖人债务，后续现金奖励先抵扣；赠出/消耗的奖励积分不足部分记原获奖人的积分追偿，不直接扣接收人的赠送余额。
- 财务“核验订单退款”只查询已经发生的退款，不发起退款，不接受手工指定“成功”或退款金额。它处理推广奖励冲正；原购买套餐/积分权益的退款撤销仍应按支付产品的售后流程办理。已核验发生退款的购买批次停止参与赠送。

## 赠送与提现

赠送仅可使用已付费、已释放、未占用、未过期且未发生退款的批次；奖励积分需单独开启，收到的赠送不能再次赠送。默认接收方需有效订阅、最低 10000 积分、每日最多 5 次、本月最多赠送月初可赠余额的 20%，当月新购从下月计入。接收批次继承来源成本和有效期。

提现默认最低 100 元、单笔最高 1000 元、每日最多 3 次/3000 元、月度最高 20000 元，手续费为 0。提交时冻结现金，运营复核后才调用商户接口。无法确定渠道结果时保持冻结，只按原商户单号查询，不重新打款。终态幂等，失败释放冻结时先抵扣已有债务。

支付宝保存加密收款资料；微信通过公众号 OAuth H5 确认身份、回到客户端输入密码绑定。微信要求确认收款时生成短期二维码，在 H5 调用官方组件；前端组件回调不代表到账，最终以渠道查单/验签回调为准。微信当前不支持超出免姓名校验范围的单笔转账（代码限制 2000 元以下）。

赠送、绑定收款账号与提现均需当前密码，共享每账号 5 分钟最多 10 次的 Redis 限流；安全缓存不可用时暂停这些资产操作。密码不进入持久存储或运营操作日志，收款信息和确认包加密保存。

# 聊天框语音输入：客户端接入说明

核对日期：2026-09-13。适用于 Web、Electron、移动端等其他客户端研发同事；本文可独立转交。线上 API 基址为 `https://www.yxciedu.com/api/v1`。

本期功能：录音 → 停止 → 转为文字 → 填入聊天草稿 → 用户确认发送。语音模型由运营按客户端配置，终端用户不选择模型。内容朗读、语音合成与实时语音对话尚未提供客户端接口。

## 1. 上线准备

1. 先完成客户端专用登录，取得本客户端用户的 `access_token`，使用 `Authorization: Bearer ...`。不能使用运营人员令牌或模型运行令牌。
2. 运营在「供应商与模型」配置语音识别协议及采购价、测试供应商连接并启用模型。
3. 运营选择正确客户端，在「客户端模型配置 → 模型配置 → 语音输入」选模型并开启。默认关闭，不会随部署自动开启。
4. 客户端只对接下面两个统一接口。不要保存供应商密钥，不要调用运营配置 API，不要把 `app_id`、`app_code`、`model` 作为语音请求的授权范围或路由参数。

Web 必须在 HTTPS 或 localhost 使用麦克风。Electron 需配置应用主页面的仅音频权限，不能全局放开浏览器权限；系统麦克风权限仍需用户允许。移动端使用本平台正常的录音权限流程。

## 2. 查询是否可用

`GET /client/speech/capability`

无请求体、无业务查询参数。返回标准包络：

```json
{
  "code": 0,
  "msg": "操作成功",
  "success": true,
  "status_code": 200,
  "data": {
    "available": true,
    "reason": null,
    "max_duration_seconds": 60,
    "daily_limit_seconds": 600
  }
}
```

| 字段 | 含义 |
| --- | --- |
| `available` | 当前客户端是否开通且模型可用。为 false 时不要申请麦克风或上传录音 |
| `reason` | 不可用原因，允许为空；可作为提示，不能解析中文内容作为程序判断依据 |
| `max_duration_seconds` | 本次录音上限，5～60 秒，默认 60；必须按返回值自动停止录音 |
| `daily_limit_seconds` | 每人每日配置上限，默认 600 秒；这是总额度，**不是剩余额度** |

未开通仍是 HTTP 200，`available=false`。能力查询成功不保证后续识别一定成功，期间运营可能调整配置。每次开始录音前重新查询；响应为 `Cache-Control: no-store`，不要永久缓存、跨账号复用。

## 3. 上传录音并识别

`POST /client/speech/transcriptions`

`Content-Type: multipart/form-data`，浏览器发送 FormData 时不要手工设置 Content-Type，交给浏览器生成 boundary。

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `audio` | 文件 | WAV 容器，PCM16 小端有符号整数，单声道，16000 Hz；时长至少 0.1 秒，最多为能力接口的单次上限 |
| `request_id` | 字符串 | 每次新录音生成一个 UUID。16～64 字符，仅字母、数字、连字符；不可使用下划线 |

不要直接上传浏览器 MediaRecorder 的 WebM/Opus、AAC 或 MP4，也不要只修改文件后缀。Web/Electron 应停止录音后解码、合并声道、重采样并编码为上述 WAV；原生客户端也遵守同一输出格式。服务端最大接受 1,924,096 字节，并检查实际 WAV 内容而不信任文件名。

```bash
curl 'https://www.yxciedu.com/api/v1/client/speech/transcriptions' \
  -H 'Authorization: Bearer <客户端用户 access_token>' \
  -F 'request_id=48bc9999-d3c2-48b8-9fdd-95227d30ca70' \
  -F 'audio=@voice.wav;type=audio/wav'
```

成功包络的 `data`：

```json
{"text": "请分析这份招标文件。", "duration_ms": 3200}
```

`text` 是普通文字，不是 HTML。空字符串表示未识别到有效语音：保持草稿不变并提示重录。`duration_ms` 是已接收音频的毫秒时长，不是识别接口耗时。服务端只返回文字和时长，不返回供应商密钥、内部模型设置或可自行更换的模型。

TypeScript 调用示例（`apiClient` 指客户端项目已有的、负责鉴权与标准包络解包的请求封装）：

```ts
const capability = await apiClient.get('/client/speech/capability', { signal });
if (!capability.available) throw new Error(capability.reason || '语音输入暂不可用');
// 用户录音并停止后，将实际音频编码为 16kHz / mono / PCM16 WAV。
const form = new FormData();
form.append('audio', wavBlob, 'voice.wav');
form.append('request_id', crypto.randomUUID());
const result = await apiClient.post('/client/speech/transcriptions', form, {
  signal,
  timeoutMs: 75000,
});
// 确认账号、会话仍与本次录音一致，再追加 result.text 到当前草稿。
// 不自动发送，不覆盖用户识别期间手动输入的内容。
```

## 4. 状态、取消与错误

建议状态：空闲 → 准备麦克风 → 录音中 → 识别中 → 空闲。录音时显示时长、停止和取消；识别时显示等待状态且保留取消入口。识别完成前禁止发送当前草稿，避免发送时序冲突。

取消、离开聊天页、切换会话、退出登录或页面隐藏时：停止 recorder、停止所有 MediaStreamTrack、清除定时器、关闭 AudioContext，并 AbortController.abort()。同时使用会话/账号标识或递增序号丢弃迟到结果。取消 HTTP 请求不承诺上游已经停止计费，因此不能自动重新提交相同录音。

| HTTP 状态 | 客户端处理 |
| --- | --- |
| 400 | WAV 内容、采样率或时长无效；提示重新录制 |
| 401 / 403 | 身份过期、错误主体或无权调用；沿用统一认证处理 |
| 409 | 同一录音已经提交；不要生成新 ID 悄悄重试 |
| 413 | 录音字节超限；提示缩短录音 |
| 422 | 缺少文件/request_id 或字段格式错误；修正接入参数 |
| 429 | 频率、并发或当日时长超限；保留草稿，提示稍后或键盘输入 |
| 502 | 上游识别失败或超时；保留草稿，允许用户重新录制 |
| 503 | 客户端关闭、模型停用、供应商或配置不可用；提示稍后重试或联系运营 |

业务失败按 `success=false`、`code!=0` 和 HTTP 状态处理，不硬编码中文错误文本。后端上游调用超时为 65 秒，客户端总请求超时建议 75 秒。不要设置自动网络重试；鉴权层刷新令牌只允许按现有统一规则处理。

服务端按认证客户端及用户计量：北京时间自然日默认每人 600 秒、每分钟最多 8 次、同时最多一个进行中的识别。失败或取消也占用已提交录音的安全时长额度。本期不扣用户积分；语音成本独立于聊天 Token，并计入运营端统一成本报表。其他客户端的语音接口与请求格式不变。

## 5. 联调验收

- 未开通时有清楚提示，键盘输入正常；用户不会看到语音模型选择。
- 权限拒绝、无麦克风、设备被占用均可恢复，不持续监听。
- 识别成功追加到现有草稿，保留用户手动输入，不自动发送。
- 空音频/空识别、过短/过长录音、网络错误和额度不足不会清空草稿。
- 取消和切换会话后麦克风指示灯关闭，迟到结果不会进入新会话或新账号。
- 同一 request_id 重复提交不会产生第二次供应商调用。
- 运营切换模型无需客户端升级；不同客户端的配置与用户额度相互隔离。

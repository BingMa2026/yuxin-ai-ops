# 模型服务开关与时长套餐：运营端实施说明

更新日期：2026-10-08。本文描述本次实际实现，取代早期方案中与此不一致的开关命名和方向。

## 1. 最终规则

运营中心 → 客户端管理 → 基本资料 → 编辑资料，新增 **启用平台模型服务**。

| 开关 | 模型配置 | 购买权益 | 使用判断 |
| --- | --- | --- | --- |
| 开启（默认） | 使用平台配置，客户端不开放自配 Key | 保留现有积分套餐、积分包规则 | 保留原有订阅、积分及网关校验 |
| 关闭 | 客户端可配置自己的模型地址、Key | 购买客户端使用天数 | 登录有效、订阅有效且未到期 |

这是每个客户端独立的配置，不影响其他客户端。运营端只管理允许自配的开关，不保存用户自己的模型 Key。

## 2. 已调整的功能

| 功能 | 实际行为 |
| --- | --- |
| 客户端管理 | 创建、编辑、详情和当前客户端上下文返回开关；编辑提交配置版本，检测并发修改 |
| 产品刊例 | 关闭开关后，新建默认是时长套餐；可填 7、30、90 或其他 1–3650 天；隐藏积分、释放计划、积分有效期、模型成本等输入 |
| 套餐模板 | 支持“积分 / 订阅时长”权益类型；时长模板积分固定为 0、释放计划为空；修改价格不自动生成积分 |
| 公共价格体系 | 允许同时保存不同权益类型模板，供不同客户端复用；切换某个客户端不会修改公共模板 |
| 刊例套用模板 | 根据当前客户端模式筛选；已有刊例不能直接修改权益类型，应新增对应类型刊例 |
| 定价策略 | 时长套餐只使用价格和折扣，模型成本及积分兑换率为 0，不要求模型毛利率配置 |
| 购买目录和下单 | 只销售与当前模式匹配的商品；后端拒绝跨模式商品及非法时长配置 |
| 支付到账 | 沿用原订单、查单、回调、补发链路；时长订单只发订阅周期，不生成积分批次或积分流水 |
| 连续购买 | 有效期限内购买不同天数套餐也累计；到期后从本次到账时间开始 |
| 订阅管理 / 用户管理 / 用户详情 | 时长模式显示订阅到期时间和剩余时长，隐藏可用积分、待释放、低积分分群、积分范围筛选、积分账户页签及人工积分调整入口；历史积分保留 |
| 退款 | 按订单快照处理；可保留权益或终止该订单剩余时长；其他订单时长保留并前移衔接 |
| 历史订单和退款详情 | 根据订单权益类型显示购买天数、订阅周期、退款后到期时间；历史积分订单仍显示积分明细 |
| 增长关联 | 关闭后禁止新增人工积分调整、积分转赠及发布积分激励；新事件不产生积分奖励，现金类奖励沿用原规则 |
| 平台模型 | 关闭后不返回可用平台模型、不签发运行令牌；旧运行令牌和网关实际调用同样复核开关 |
| 平台语音 | 同属平台模型服务；关闭后能力接口返回不可用，并拒绝平台转写请求 |

时长套餐上架和下单时，首购价、续费价、折扣后的执行价必须大于 0；暂不支持零元时长试用及自动扣款续费。天数为连续 24 小时，计算使用服务端 UTC 时间。

时长用户的零余额积分账户仅复用现有财务事务锁，不代表积分权益。原有历史积分数据保留，历史结算及退款继续按旧快照处理，不自动兑换成天数。

配置入口：顶部选择目标客户端 → 预算中心 → 产品刊例 → 新增刊例 → 填写“订阅天数”、首购价和续费价 → 保存并上架。开关关闭后新建默认为时长套餐；旧积分刊例不能直接改为时长套餐。切换开关不会自动赠送天数，未开通订阅的用户仍显示“未开通”。

## 3. 续费、暂停与退款

正常续费：新到期时间 = max(当前有效到期时间, 本次到账时间) + 购买天数。例如剩余 10 天，再买 30 天，最终剩余约 40 天。

重复支付回调和重复权益补发不会重复增加天数。下单后的套餐改价或改天数，不影响该订单快照。

运营取消订阅后，接口返回 suspended。再次购买可以累计期限，但不会自动解除运营取消状态，恢复使用仍需运营处理；期限按自然时间流逝，不因取消而冻结。

退款选择“终止剩余权益”时，只扣掉该订单尚未使用的时间，后续购买时间前移接续。即使金额只是部分退款，选择终止仍终止该订单全部剩余时长。已使用的时间不回滚，退款金额继续由原财务流程审核。

退款预览令牌核对持久化订阅记录，避免正常时间流逝导致确认总是失败；续费或其他权益变更后，需要刷新预览再提交。

## 4. 模式切换与兼容边界

- 老客户端应用迁移后默认开启，老模板、刊例和订阅默认是 credits，历史订单缺失权益类型时按积分处理。
- 未完成支付订单不再阻止切换，运营端确认框提示后允许保存。旧订单保留原始快照；切换后付款若权益类型不匹配，记录已支付但不自动发放权益或推广奖励，可在财务中心“交易订单”筛选“权益未到账”核对或退款。自动补单、人工查单均不得跨模式发放权益。
- 存在未结束的订阅或未结束的有效订阅周期时，禁止直接切换，需要先处理已有权益或退款。即使订阅被运营取消，其未结束周期也不能直接跨模式改写。
- 切换成功时自动下架不适用的在售刊例；不会自动上架另一模式商品，需运营配置价格后上架。
- 现有积分余额不删除、不换算为天数。切回平台模式后是否仍可用，依照各积分批次的原有效期。
- 已受理调用仍按原规则完成结算，不因关闭开关免单；关闭后新的平台模型和语音请求被拒绝。
- 模式变更、下单、回调、策略保存等沿用事务锁控制，避免同时发生时按错误模式售卖。
- 开关保存前有确认说明，但不会自动检查安装在用户电脑上的客户端版本。应先发布支持本接口的客户端，再实际关闭开关。

## 5. 客户端对接接口

登录成功后调用 `GET /api/v1/client/runtime-config`，使用原客户端登录令牌。登录接口原返回结构不变。

标准响应的 data 示例（服务端动态产生时间和剩余秒数）：

```json
{
  "schema_version": 1,
  "app_id": 1,
  "user_id": 100,
  "platform_model_enabled": false,
  "allow_custom_model": true,
  "billing_mode": "duration",
  "policy_version": 2,
  "server_time": "2026-10-08T08:00:00Z",
  "refresh_after_seconds": 3600,
  "authorization": {
    "status": "active",
    "can_start_task": true,
    "expires_at": "2026-11-07T08:00:00Z",
    "remaining_seconds": 2592000
  }
}
```

响应设置 `Cache-Control: no-store`，app_id、user_id 从认证上下文取得。

| authorization.status | 含义 |
| --- | --- |
| platform | 平台模式，仍须走原模型网关及积分校验；can_start_task 不代表免费或无限调用 |
| not_purchased | 尚未购买时长订阅 |
| active | 时长订阅有效 |
| expired | 时长已结束或当前尚不处于有效区间 |
| suspended | 运营取消了订阅，不能启动任务 |

`allow_custom_model` 决定是否显示地址和 Key 设置；未购买或过期用户仍可填写设置，但启动付费任务应检查 `authorization.can_start_task`。

客户端每 1 小时（refresh_after_seconds=3600）同步一次；登录、休眠恢复和支付成功后立即刷新。普通窗口切回前台时，仅在缓存超过 1 小时后刷新。开始、重试或恢复收费任务时先在本机检查已同步的授权和到期时间，只有配置超过 1 小时才重新请求，不逐任务联网查询。以服务端时间结合单调计时判断到期，到期后立即阻止新收费步骤，不额外放行 1 小时。缓存超过同步期限且刷新失败时暂停新收费任务，不能永久使用旧授权。运营取消订阅、退款或模式变更通常在下一次成功同步生效；正常在线时感知延迟不超过约 1 小时，平台网关仍按服务端当前状态校验。

原 `/client/model/config` 增加 `platform_model_enabled`、`allow_custom_model`，关闭时返回空模型和路由。原 `/client/billing/catalog`、订单快照及订阅接口增加 `entitlement_kind`，保留已有字段。

**本次未修改桌面客户端。** Key 的本地安全保存、自有模型请求、客户端页面切换、离线规则及本地任务开始前的授权检查，需在客户端后续实现。运营服务无法直接阻止完全离线、被修改过的客户端执行其自己的模型调用。

## 9. 人工调整使用天数（2026-10-10 增补）

实现位于运营端 `D:\2026\python\yyd`。桌面端使用 `D:\2026\python\招投标产品\bid-agent-client`，本增补不需要修改桌面接口；客户端点击“刷新权益”获取新的到期时间。不手动刷新时沿用客户端既有同步周期，运营扣减或停用不会即时推送到离线客户端。

### 操作入口与规则

选择目标客户端，进入 **用户运营 → 用户管理 → 目标用户的操作菜单 → 调天数**。仅关闭平台模型服务的时长模式显示该入口，积分模式继续使用“调积分”。

- 增加天数：选择当前客户端的时长套餐，输入 1～3650 的整数天数及至少 2 个字的原因。未购买也可直接开通，无需支付渠道；有效期内从原到期时间延长，已过期从操作时间起算。关联套餐仅提供权益归属，不改变本次输入天数、不收款；没有时长套餐时，先在“预算中心 → 产品刊例”创建。
- 扣减天数：从最后的未使用周期开始扣减；超过剩余时长时立即到期，不能扣成负数。提交前确认用户及预估到期时间，历史记录保留申请天数和实际扣减量。
- 调整不会解除账号停用或订阅停用。取消状态的订阅加天数后仍处于停用状态。
- 保存操作人、原因、调整前后到期时间及涉及的权益周期，弹窗显示最近 20 条记录。人工增加的周期独立于支付订单，支付退款保留其余合法时长。
- 重试相同请求只执行一次；页面打开后若到账、退款或其他运营操作改变了到期时间，拒绝旧请求并提示刷新后重新确认。

### 接口及权限

`GET /api/v1/operations/billing/subscriptions/users/{user_id}/duration` 返回服务端时间、订阅状态、到期时间、剩余秒数、可选时长套餐及调整记录。

`POST` 同一路径接收 `direction`（grant/deduct）、`days`、`catalog_plan_id`（增加时选择）、`reason`、`idempotency_key`、`expected_expires_at`（未开通为 null）。读取返回的到期时间须原样提交，保留时区及小数秒，用于防止覆盖其他操作。两个接口都要求运营身份、当前客户端范围与 `workspace:user:management:duration` 权限。请求不能指定其他 app_id；客户端用户不能调用。

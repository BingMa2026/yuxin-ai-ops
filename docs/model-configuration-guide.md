# 供应商与客户端模型配置使用说明

资源中心包含两个独立菜单：**供应商与模型**维护平台资源，**客户端模型配置**管理右上角当前客户端的授权与业务路由。API Key 仅在供应商连接中填写，不需要在客户端授权中重复配置。

## 一、接入供应商

1. 在「供应商与模型」中搜索并选择供应商，点击「配置连接」。
2. 填写账号名称、内部编码、API 地址和供应商要求的凭据。地址默认取自供应商模板，使用代理或自建服务时按实际地址修改。
3. 新账号可以先「测试连接」，再「保存账号」。表单测试不会保存账号或模型目录。
4. 保存后点击「测试并发现模型」，确认连接正常，然后启用账号。
5. 在模型目录中核对能力、上下文和采购成本，启用需要提供给客户端的模型。不能自动发现时，可使用「手工添加」。

编辑已保存账号时，密钥留空表示保留原密钥；更换后保存，再测试连接。采购价格与客户端积分不是同一个概念：采购成本按元/百万 Token 记录，具体版本在「价格版本」中维护。财务连接用于余额、账单与成本核对，凭据独立于推理 API Key。

## 二、为客户端授权模型

先确认全局顶栏选中的客户端。进入「客户端模型配置」并点击「授权模型」。可选目录来自已启用账号下的已启用模型。

| 字段 | 如何填写 |
| --- | --- |
| 供应商模型 | 选择实际调用的底层模型 |
| 公开模型编码 | 例如 `bid-qwen`，客户端调用用的稳定标识，保存后不可修改 |
| 客户端显示名称 | 例如「千问 · 标书助手」，面向最终用户 |
| 客户端可见 | 是否在客户端模型列表展示 |
| 允许用户选择 | 是否允许用户主动切换到此模型 |
| 设为默认模型 | 每个客户端只保留一个默认模型；不能替代业务路由 |
| 排序 | 数字越小越靠前 |

后台业务专用模型可以不对用户展示，但仍需授权并启用。停用授权会影响依赖它的业务，操作前应检查主模型与降级模型。

## 三、配置业务路由（必须）

根据客户端实际使用的功能分别配置「默认聊天」「文档理解」「语义审核」。

1. 点击「配置路由」，选择业务场景，填写容易识别的路由名称。
2. 选择已授权并启用的主模型。
3. 按期望顺序选择降级模型；主模型调用失败时，按路由策略尝试后续模型。不要重复选择主模型。
4. 设置超时（秒）和最大输出 Token，与供应商模型的能力限制匹配。
5. 需要调用工具时勾选「允许工具调用」，同时确保所选模型支持工具。需要用户切换模型的场景勾选「允许用户选模型」。
6. 保存。再次保存相同业务场景会更新该路由，而不是新增一条并行路由。

例如：授权一个支持工具的聊天模型，将其设为默认模型，并为「默认聊天」设置该授权为主模型。如果客户端还会使用文档理解或语义审核，也需分别配置对应路由。具体能力以供应商模型的实际支持情况为准。

## 四、验证与排查

重新进入客户端或刷新模型配置，检查模型显示名称、默认项和可选范围，再实际执行对应业务。供应商连接测试成功不等于完整客户端业务已验证。

- **没有可授权模型**：确认供应商账号与目录模型都已启用。
- **客户端看不到模型**：确认当前客户端正确，授权启用且勾选可见。
- **能看到但无法选择**：检查授权的「允许用户选择」和业务路由的「允许用户选模型」。
- **已授权仍无法调用**：检查对应场景是否配置路由，主模型是否启用，供应商连接是否正常。
- **切换客户端后配置不同**：授权和路由按当前客户端隔离，需分别配置。

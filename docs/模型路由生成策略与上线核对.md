# 模型路由生成策略与上线核对

本文对应 `codex/client-runtime-completion-contract` 的待发布代码。已完成本地隔离测试；没有部署、修改生产路由或调用付费模型。运营表单由同批改造接入，必须先确认后端支持新契约，再开放新控件。

## 1. API 契约

继续使用既有 `POST /api/v1/operations/models/routes`，应用范围取运营令牌的当前客户端。新增字段如下；不提供任意供应商参数编辑器。

```json
{
  "business_code": "document_intelligence",
  "name": "文档智能",
  "primary_binding_id": 123,
  "fallback_binding_ids": [],
  "timeout_seconds": 120,
  "max_output_tokens": 8192,
  "allow_tools": false,
  "allow_user_model": false,
  "status": "active",
  "generation_settings": {
    "policy_version": "qwen3.8-bounded-v1",
    "enable_thinking": true,
    "thinking_budget_tokens": 4096,
    "total_timeout_seconds": 600,
    "response_format": "json_object"
  }
}
```

示例中的绑定 ID、启用状态及能力开关须按目标客户端的实际配置填写，不是生产变更指令。各字段约束：

| 字段 | 含义和边界 |
| --- | --- |
| `generation_settings` | 新建时缺省/`null` 为旧策略；修改既有路由时省略字段保留原策略，显式 `null` 才停用。旧表单修改名称或答案上限不会自动降级。 |
| `policy_version` | 仅接受 `qwen3.8-bounded-v1`；未知字段和未知版本拒绝。 |
| `enable_thinking` / `thinking_budget_tokens` | 开启时预算为 1～262144；关闭时必须为 0。不开设 `reasoning_effort`，避免与预算参数冲突。 |
| `max_output_tokens` | 继续表示答案上限。治理策略要求显式配置 1～131072；调用请求超过路由上限仍在预占前拒绝。 |
| `total_timeout_seconds` | 1～720 秒，从开始准备请求计时，覆盖数据库准备、连接、备用候选和整个流读取；收到推理增量不会重置它。 |
| `timeout_seconds` | 原有路由/供应商传输等待上限仍有效，取二者较小值。它与整次时限分别生效。 |
| `response_format` | 仅 `text` / `json_object`。后者要求实际系统或用户提示中出现 JSON 指令，不由网关偷偷改写提示。 |

适配仅接受实际模型 ID `qwen3.8-max`、`qwen3.8-max-0902`、`qwen3.8-flash` 和兼容协议；不能根据公共模型别名猜测能力。主模型、备用模型、用户替代模型均校验。当前治理策略覆盖文本输入；图片、音频、视频及 URL 材料不使用文本字节数冒充 token 费用，遇到这些输入明确拒绝。模型目录的视觉/PDF 能力标志保持其实际含义。

供应商请求实际发送 `max_tokens`（答案）、`thinking_budget`（思考）、`enable_thinking`、`response_format`。不同时发送 `reasoning_effort` 或 `max_completion_tokens`。后者包含思考与答案，不能在不改变旧答案上限语义的情况下直接替换。[参数定义](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)

`GET /api/v1/client/model/config` 公开规范化 `generation_settings` 和 `generation_policy_status`：`GOVERNED` / `LEGACY_UNMANAGED`。既有配置版本失效机制继续生效；运行前解析的配置冻结在本次 `PreparedRequest`，后续编辑不修改已准备请求。完成响应和 SSE `done` 同样包含策略诊断字段。客户端模型身份应包含规范化配置、策略版本及既有配置版本；旧冻结任务不得暗用新配置继续。

## 2. 预算、时限与用量证据

- 输入预占采用 UTF-8 字节数加消息封装余量的保守估算，标识为 `utf8-bytes-framing-v1`。上限 131072，超过直接拒绝，不截小估计值；目录已有上下文容量时还检查输入、思考、答案的合计。
- 费用预占包含输入、答案和思考。输入采用冻结价格中普通输入/缓存读取/缓存创建的最高单价；答案采用输出单价；思考采用推理单价，无单独推理价格时回退输出单价，与结算路径一致。多个候选取最大预占。积分计量包含答案与思考。
- 显式治理策略余额不足时整次拒绝，不静默缩小思考或答案预算。旧 `null` 路由保留原有预占与答案缩减行为。
- 既有预占在 15 分钟后释放。本策略最多生成 720 秒，预留至少 180 秒供关闭连接和结算。总时限在准备时开始，不能通过换备用模型重新获得一段完整时限。流输出路径使用逐次有界等待，避免将跨 `yield` 的超时上下文施加给 ASGI 调用方。
- 仅连接建立前的明确失败允许备用模型。读取/写入超时或供应商已响应后，不自动发起第二次生成，避免用一次最大候选预占覆盖两次可能付费的执行。
- `model_usage.execution_snapshot` 保存策略、预算依据、候选实际模型身份、超时、已用绑定及摘要哈希；不保存正文、密钥或请求 URL。实际用量零值不会被估算替换。
- 成功传输、完整用量、客户端收到正文是不同事实。缺输入数量或思考明细、流中断、取消时，保留 `usage_complete=false` / `usage_incomplete`；已观察的部分用量标为 `observed_partial_usage`。最终用量超过预算时保留 `budget_exceeded` 和实际供应商成本，不把已有结算封顶伪称为费用足额保证。供应商账单仍需独立对账。

官方将 `thinking_budget` 定义为思考上限，达到后转入答案；本策略依据该契约计入预占，并保留偏差检测。没有通过真实供应商调用证明所有边界无误，也没有把估计输入或无回执费用当成实际账单。[思考长度说明](https://help.aliyun.com/zh/model-studio/deep-thinking)

流式调用持续有数据可避免传输空闲超时，但不保证完整 JSON 或正确提取。非流式请求等待完整响应期间仍受原有传输超时约束。原有补丁保留实际 `finish_reason` 和实际答案预算；缺可靠结束原因、截断、过滤或缺终结证据不能被客户端视为完整业务结果。[结构化输出能力](https://help.aliyun.com/zh/model-studio/qwen-structured-output)

## 3. 有限错误分类

错误只公开固定中文消息与以下类型，不公开供应商响应正文、URL 或凭据。供应商授权故障应提示运营排查，不能提示客户端用户重新登录。

| SSE `error.code` | 非流式 HTTP / 包络数字 code |
| --- | --- |
| `UPSTREAM_TOTAL_TIMEOUT` | 504 / 50401 |
| `UPSTREAM_IDLE_TIMEOUT` | 504 / 50402 |
| `UPSTREAM_CONNECT_TIMEOUT` | 504 / 50403 |
| `UPSTREAM_RATE_LIMITED` | 503 / 50302 |
| `UPSTREAM_AUTH_REJECTED` | 503 / 50303 |
| `UPSTREAM_REQUEST_REJECTED` | 502 / 50201 |
| `UPSTREAM_SERVER_ERROR` | 503 / 50304 |
| `UPSTREAM_PROTOCOL_ERROR` | 502 / 50202 |
| `UPSTREAM_UNAVAILABLE` | 503 / 50301 |

旧路由原错误类型继续兼容。`LEGACY_UNMANAGED` 是诊断状态，不是可靠完成或退款证明。

## 4. 可审阅的上线顺序（尚未执行）

1. 固定本次后端、运营表单和客户端对应提交/构建产物；保留原有 `finish_reason` 补丁。导出现有路由配置及数据库备份，记录迁移头。检查正在执行请求和结算状态，不能通过强杀执行器把未知请求标为未扣费。
2. 在隔离副本演练 `20260913_speech_input → 20260914_generation_policy`。只新增路由 JSON 和用量 JSON 可空列，历史行保持 `null`；不自动回填策略、不改已有预算、供应商账号或应用授权。核验升级后旧路由仍可读取。
3. 得到明确生产发布授权后，限定更新本项目后端及迁移。确认所有服务实例均支持新 schema 和运行策略，再发布新运营表单。不能先上线 UI，让旧后端静默忽略新字段。
4. 先核验配置读取、权限范围、超额预算拒绝、未配置路由兼容等不消耗模型费用的行为。确认目标实际模型、定价和余额能够支撑所选预算；路由策略启用是另一项具体、可审阅配置变更，不随迁移自动发生。
5. 按最终批准的预算和业务路由启用策略，再在授权范围内做一次受控供应商调用，核对真实 payload、结束原因、实际思考/答案用量、预占结算、超时分类以及客户端完整性门禁。该验证未执行前，不宣布真实长思考或业务准确率验收通过。
6. 回退优先停用受影响路由并回退对应后端/UI，保留兼容的新增列和历史执行证据；不能以静默改为旧策略继续发起请求代替回退。不得运行删除已有执行快照的降级。确需数据库降级时应使用已演练的匹配备份，明确处理期间新增数据。迁移自身会拒绝直接删除非空策略或用量证据。

运营表单需要：显式启用开关、只读策略版本、思考开关及预算、答案上限、总时限、格式选择、预算摘要，以及“本策略目前仅覆盖文本”的说明。不要修改模型的真实视觉能力来隐藏不兼容输入；不要用自由 JSON 表单代替这些有限字段。

## 7. 同批发布的本人请求结算回执

新增 `GET /api/v1/client/model/requests/{request_id}/receipt`，复用 `ModelClientRouter`、现有客户端 access token 依赖和标准响应。公开 `model-request-receipt/v1` 有限类型，完整字段与客户端规则见[客户端集成文档 §8.7 和接口 57](客户端集成文档.md#api-57)。不新增模型执行 API，不保存或返回模型正文，不返回供应商秘密、成本定价或完整 `execution_snapshot`。

`request_receipts.ModelRequestReceiptService` 对本人应用/用户下的用量与预占执行一次 SELECT，键集合及两个 JOIN 均约束身份和软删除。单语句保持 PostgreSQL READ COMMITTED 下同一读取快照，禁用 autoflush，不加行锁，不调用 `release_due`、账户维护或结算。只有预占时执行情况仍未知；预占被释放不表示模型从未执行；历史 `usage_complete` 保留 null。`reported_charged_credits` 与预占真实 `charged_credits` 分开，不能把孤立用量记录猜成结算完成。

DTO 按固定 UTC JSON 计算 `receipt_sha256`，不含读取时钟；重复状态得到相同摘要，实际后续状态得到新摘要。仅返回有限错误分类，响应禁止缓存。跨用户、跨应用、软删除及无记录统一 404。客户端必须按原调用账号查询并追加补充证据，不能用 `SUCCEEDED` 补写缺失的响应或业务完成。

该接口读取本包新增的 `model_usage.execution_snapshot.usage_complete`，没有额外表结构变化；必须连同 `20260914_generation_policy` 迁移和支持它的所有后端实例一起上线。发布前先验证 schema/认证/404/只读回执，不需要发起模型请求。未部署服务的 404 不能解释为原请求没有费用。

正式先验：`tests/test_model_request_receipts.py` 18 项失败（5.18 秒），均为新增接口/服务尚未实现的能力，不是 18 个旧计费错误。首轮实现 16 通过、2 失败，定位为 SQLite 将 JSON 布尔提取成数字；已通过 JSON 类型门禁再转换布尔，拒绝数字 0/1、字符串 true/false 或非法字符串伪装完整性。PostgreSQL 分支使用 `json_typeof` 同样先验证类型，不直接强制转换未知字符串。
